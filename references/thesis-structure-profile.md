# 论文结构 Profile

本文件是结构审查用的可配置模板，默认依据用户当前论文的章节骨架整理。用于其他论文时，先确认固定标题、角色标题形式和可选章节是否沿用，不得直接把当前论文的角色名称或图号套用到其他论文。

## 0. 审查前必须确认

- **总体功能模块图**：按图题和图中内容识别，不假定编号一定是“图3.1”。
- **角色清单**：从总体功能模块图读取角色名称、数量和从左到右的顺序。
- **章节标题中的角色名**：这不是从总体功能模块图读取的内容，而是后续命名约定。默认直接使用图中的角色名称；如论文采用简称（例如图写“系统管理员”、标题写“管理员”），必须在用户确认后记录映射。
- **第4章写法**：角色型或功能型。用户未明确选择且无法判断时，按角色型处理并请用户确认。
- **唯一准稿**：同一论文存在多个副本、备份、旧版截图或旧版 PDF 时，先确认唯一准稿路径；只读取该版本，不跨版本拼接结构或分页结论。
- **固定标题范围**：第1、2、3、5章按本 profile 检查；需要改标题框架时，先由用户确认新 profile。

如果缺少总体功能模块图，或图中的角色名称、数量、左右顺序无法辨认，停止结构结论，要求用户提供图或确认角色清单。只有采用功能型第4章时，才需要进一步确认角色分支下的功能节点。

## 0.1 提取角色、顺序与所需功能名（按第4章写法使用）

总体功能模块图的默认含义：

1. 第一层：论文题目或系统名称；
2. 第二层：角色；
3. 第二层角色节点以下的所有功能节点：该角色对应的功能；
4. 第三层、第四层或更深层的纵向位置只是图形排版结果，不单独定义“页面模块”或“非功能分类”。

提取规则：

- 角色名称、角色数量和左右顺序只能来自第二层，不能根据第2~5章标题反推。
- 功能型第4章的“具体功能名”来自每个第二层角色分支下的所有功能节点，包括第三层及更深层。
- 功能型按角色连线、分支和父子关系判断功能归属，不能仅按纵向层数漏掉节点；节点归属不清时先向用户确认。
- 角色型第4章不要求从图中逐项提取三级功能标题，也不以图节点数量限制角色小节的功能数量；三级标题按该项目中对应角色的实际功能编写。
- 角色型不同角色可以包含同名功能（例如登录），不因名称重复而合并、删除或改标题。
- 标题后缀按结构模式确定：角色型三级标题使用“功能名+功能”，功能型二级标题使用“功能名+功能实现”；名称已经包含相应后缀时不得重复叠加。

## 1. 固定标题骨架

以下标题按“编号 + 文字 + 层级”严格匹配。角色型章节标题中的角色名按用户确认的标题写法替换；如果标题写法与图中名称相同，只保留一个名称。

### 第1章

```text
第1章 绪论
1.1 系统研究的背景与意义
1.1.1 研究背景
1.1.2 研究意义
1.1.3 实现价值
1.2 国内外研究现状
1.2.1 国内研究现状
1.2.2 国外研究现状
1.3 系统研究内容
1.4 系统设计结构
```

### 第2章

```text
第2章 系统分析
2.1 系统功能需求分析
2.1.X <章节标题中的角色名>模块
2.2 系统非功能需求
2.2.1 系统性能需求
```

规则：

- 2.1下的三级标题数量必须等于总体功能模块图中的角色数量。
- 2.1.X的顺序必须与总体功能模块图从左到右一致。
- 每个角色小节应对应说明该角色的功能需求。
- 2.2.1必须保留并严格匹配。
- 2.2.2及之后的小节是可选内容；可以没有，也可以有多个。存在时不得要求删除，标题不必固定为当前论文的“系统安全性需求”“系统可扩展性与兼容性需求”，内容合理即可。

### 第3章

```text
第3章 系统设计
3.1 系统总体设计
3.2 系统功能模块设计
3.2.X <章节标题中的角色名>功能模块设计
3.3 系统数据库设计
3.3.1 数据库概念模型设计
3.3.2 数据库表结构设计
```

规则：

- 3.1应包含一段或多段文字说明，并配总体功能模块图。
- 3.2下的三级标题按总体功能模块图的角色设置，数量和顺序必须一致。
- 3.2.X的小节内容应包含对应角色的功能说明和对应功能流程图。
- 3.2.X标题不沿用当前论文的固定文字，而以确认后的章节标题角色名替换。角色型图题、表题和简易流程图/用例图中的角色节点也应使用同一名称。
- 除3.2.X外，本章其余一级、二级、三级标题严格匹配上面的骨架。

### 第4章

固定：

```text
第4章 系统实现
4.1 系统主界面
```

第4章有两种允许写法，由用户选择；无法判断时默认角色型。

#### 角色型（推荐，用户当前论文采用）

```text
4.2 <章节标题中的角色名1>功能模块实现
4.2.X <具体功能名>功能
4.3 <章节标题中的角色名2>功能模块实现
4.3.X <具体功能名>功能
4.4 <章节标题中的角色名3>功能模块实现
...
```

规则：

- 每个角色对应一个二级标题，顺序与总体功能模块图一致。
- 角色下的功能数量按该项目中该角色的实际功能设置，不受总体功能模块图节点数量限制。
- 角色型的三级标题应直接指向具体功能；当前论文采用“具体功能名+功能”的形式，不以“功能实现”作为硬性后缀。
- 这里的“具体功能名”来自项目中的实际角色功能，不要求与第二层角色分支下的功能节点逐项对应；不同角色可以出现同名功能，例如各角色都可能有登录功能。
- 每个功能应包含功能说明、功能图和核心代码。

#### 功能型

```text
4.2 <具体功能名>功能实现
4.3 <具体功能名>功能实现
...
```

规则：

- 一个具体功能对应一个二级标题。
- 功能顺序应与总体功能模块图中的角色顺序及角色内功能顺序一致。
- 功能型的二级标题使用“具体功能名+功能实现”的命名方式。
- 这里的“具体功能名”必须来自第二层角色分支下的任一功能节点，包括第三层及更深层；不能从现有章节标题自行推断。
- 每个功能应包含功能说明、功能图和核心代码。

### 第5章

```text
第5章 系统测试
5.1 测试目的
5.2 测试内容
5.2.X <章节标题中的角色名>功能模块测试
5.3 测试结论
```

规则：

- 5.2下的三级标题数量必须等于总体功能模块图中的角色数量。
- 5.2.X的顺序必须与总体功能模块图从左到右一致。
- 每个角色测试小节应包含一段或多段文字说明及测试用例表。
- 测试用例表应按学校要求使用三线表；跨页时重复表头并添加续表题。
- 除5.2.X外，本章其余一级、二级、三级标题严格匹配上面的骨架。

## 2. 角色顺序判定

权威顺序只有一个：**总体功能模块图中角色的从左到右顺序**。

应用范围：

- 2.1.X角色模块；
- 3.2.X角色功能模块设计；
- 第4章角色型写法中的角色二级标题；
- 5.2.X角色功能模块测试；
- 明确并列列出全部角色的正文句子。

不应用范围：

- 4.1等一般界面使用流程；
- 单纯描述某个用户操作先后顺序的句子；
- 未形成角色并列关系的普通叙述。

发现章节角色顺序与图不一致时：

1. 不自行重排或改名；
2. 向用户说明图中顺序和正文顺序；
3. 让用户确认以哪一处为准；
4. 用户确认后再修改，并重新更新目录和分页。

## 2.2 角色名称一致性

- 角色型标题（2.1.X、3.2.X、第4章角色型、5.2.X）统一使用用户确认的“章节标题中的角色名”。
- 角色型图题、表题和简易流程图/用例图中的角色节点，也使用同一名称。
- 正文叙述允许使用简称，但必须由用户明确允许；例如正文可写“管理员”，标题和图表仍写“系统管理员”。
- 真实软件截图中的界面账号名称属于原始运行界面，不强制改成角色标题名；除非用户明确要求替换截图或图片内文字。
- 发现标题、图题、表题或示意图角色名不一致时，先向用户确认，再修改并更新目录和分页。

## 3. 结构审查报告字段

每个结构问题至少记录：

- 位置：章节号、标题层级、页码；
- 权威来源：总体功能模块图中的角色/顺序或其他已确认 profile；
- 证据：实际标题或缺失内容；
- 影响：是缺角色、顺序不一致、缺流程图、缺实现、缺测试表，还是可选章节被误删；
- 最小改法：只改标题/移动内容/补图或表的范围；
- 页数影响：是否可能改变分页。

## 4. 当前论文的示例角色映射

仅在用户确认“当前论文沿用此 profile”时使用。以下标题角色名是已确认的章节标题写法，不是从总体功能模块图直接读取的名称：

```text
总体功能模块图角色：系统管理员、知识专员、用户
2.1中的角色名：系统管理员、知识专员、用户
3.2中的角色名：系统管理员、知识专员、用户
第4章：角色型
5.2中的角色名：系统管理员、知识专员、用户
```

示例映射不是通用常量。换论文时必须重新从该论文的总体功能模块图读取角色名称、数量和顺序；章节标题中的角色名另行确认。当前论文为角色型第4章，不另外建立“图节点到三级功能标题”的强制映射，也不得因跨角色重名而合并、删除或改名。
